# Phase 5 — UI commonality implementation plan

Planning inventory as of September 2026. This is a handoff for a later migration, not an instruction to change application behavior now. The [roadmap](../../ROADMAP.md) defines the phase outcome; the root [design language](../../DESIGN_LANGUAGE.md) defines the compact interaction contract.

## Scope and starting point

Keep four independent applications and their vocabulary. Share a component only when two real consumers need the same presentation behavior. First align the existing implementation in one app, validate it, then move the stable presentation into `packages/ui` and adopt it incrementally. `packages/data-ui` already owns Phase 4 file and maintenance UI; extend it only for file-specific presentation. Domain derivation, queries, mutations, upload policy, and navigation routes stay in apps.

The Phase 3 [audit](../phase-3/architecture-audit.md) selected Taxbook for theme mechanics and Tenure plus Passbook for period coverage. The code has moved since that audit: `packages/ui` already contains button, card, badge, alert dialog, and progress primitives, consumed by Passbook and Tenure; `packages/data-ui` already supplies `FileDropzone`, `FilePreview`, `FileViewerPage`, and data status UI to those apps. Taxbook and First Aid still have local shadcn primitives. Treat those packages as the starting point, not as new work to recreate.

## Progress

Shared form primitives live in `packages/ui`. Apps import them from `@yourtoolshq/ui/<component>` directly. Money and percent fields use shadcn `InputGroup` text addons (`$`, `%`).

Adopted since that starting point:

- Theme: Taxbook's light/dark/system provider is shared. Passbook, Tenure, and First Aid keep their own accent hues and now have matching dark tokens, a persisted theme control on General, and theme-aware toasters where a toaster already exists. Data & backups stays storage only.
- Period coverage: `@yourtoolshq/ui/period-coverage` supplies the year control, grid/list, cell, and legend. Tenure pay periods and Passbook statement periods pass cells, tones, and actions. Derivation, status rules, N/A mutations, and sheets stay in the apps.
- Document actions: the identical open/edit/delete row lives in `@yourtoolshq/data-ui` as `DocumentActionButtons`. Confirm, invalidation, and labels stay in the apps.
- Route states: each app has `loading`, `error`, `global-error`, and `not-found` with its own copy and a retry or overview link.
- Numeric entry: `@yourtoolshq/ui/decimal-entry` normalizes `.89`, `147.3`, and simple `+ - * /` expressions on blur. Taxbook paycheque amounts and Tenure paycheck amounts use it. Range and rounding stay in the apps. A percent variant is still guidance until a second percent form needs the same commit behavior.

Sheet, dialog, and alert-dialog choices are already in the design language. What is still open is in [remaining.md](./remaining.md): an optional sidebar frame, percent expressions only if a percent field needs the money commit behavior, and dates plus one-off visuals that stay in the apps.

## Representative screens and exit test

Use fictional or empty data. Check Taxbook tax document or paycheque form and settings theme; First Aid visit/document flow; Passbook account statement periods and upload/delete; Tenure employment pay periods and stub upload/delete. Compare desktop and narrow viewport, keyboard focus, accessible names, light/dark, pending/error/empty, and file preview where applicable.

Phase 5 is complete when every app follows the documented interaction choices, the shared primitives and two proven cross-app presentation patterns are available and adopted where relevant, and the design language tells an agent what to choose without importing app business logic into shared packages. Full visual uniformity and migration of every local component are not required.
